# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Receipt scanner: users pick a receipt photo, OCR **in the browser** (Tesseract.js) extracts **store name, date, total**, and the result is stored in Convex. A modal lists every stored receipt with Previous/Next pagination, and a second modal lists the supported stores the same way (`src/components/page-controls.tsx` holds the shared `usePages` hook, which pages over Convex `usePaginatedQuery`). It's a single Next.js 16 app (App Router, Tailwind v4, shadcn/ui) at the repo root, deployed to Vercel, plus the Convex backend in `convex/`. There is no OCR server and no CDN. The Tesseract.js worker, its WASM core and the eng+spa traineddata are self-hosted from `public/tesseract/`.

## Commands

```bash
npm run dev                # Next.js dev server (predev copies the Tesseract.js assets)
npx convex dev             # Convex dev deployment; regenerates convex/_generated (keep running)
npx tsc --noEmit           # type-check
npm run lint               # eslint (convex/_generated is ignored)
npm run build              # prebuild copies the Tesseract.js assets
npm test                   # parser tests (node:test, Node's built-in TS type stripping)
node --test --test-name-pattern="US receipt" src/lib/ocr/parser.test.ts   # single test
npx convex env set CONVEX_SERVER_SECRET <value>   # must equal CONVEX_SERVER_SECRET in .env.local
```

`public/tesseract/` is generated by `scripts/copy-tesseract-assets.mjs` from `tesseract.js`, `tesseract.js-core` and `@tesseract.js-data/{eng,spa}` (gitignored). Files under `src/lib/ocr/` import each other with explicit `.ts` extensions (`allowImportingTsExtensions`) so that `node --test` can run them directly. Keep `parser.ts` and `preprocess.ts` free of DOM/Node APIs and TS-only syntax that type stripping can't handle (enums, parameter properties, namespaces).

## Next.js version caveat

`AGENTS.md`: this is Next.js 16 and APIs/conventions differ from older versions. Read the relevant guide in `node_modules/next/dist/docs/` before writing Next.js code. Cache Components is enabled, so don't add `export const runtime` to routes (Edge is deprecated).

shadcn here uses the **base-nova** style built on **Base UI**, not Radix. Use `render={<Button />}` instead of `asChild`. `cn` is imported from the `cn` package (shadcn's own; `src/lib/utils.ts` re-exports it). `Table` has a local `containerClassName` prop that lets sticky headers work inside `ScrollArea`.

## Scan request flow (spans several files)

1. `src/components/receipt-scanner.tsx` calls `scanReceipt(file)` (`src/lib/ocr/scan.ts`), which runs the OCR in the browser (see below), then POSTs the extracted fields as JSON to `/api/scan`. Selecting a file calls `loadOcrEngine()` early so the download overlaps with the preview. The image never leaves the browser.
2. `src/app/api/scan/route.ts` checks same-origin, then `readResult()` sanitizes the untrusted fields: the store must be a name in the Convex `stores` table (fetched with `api.stores.list`), the total a finite number above 0, the currency `USD`/`CLP`, and the date `YYYY-MM-DD`. Anything else becomes null. It then calls `getIdentity()` (`src/lib/server/identity.ts`). That function gives the browser a random UUID in the httpOnly `receipt_uid` cookie and HMAC-hashes both the cookie id and the IP with `CONVEX_SERVER_SECRET` into `userKey` / `ipKey`. Raw IPs are never stored.
3. `api.scans.reserve` (Convex mutation) enforces every limit and inserts a `pending` row in `scanEvents`. Convex mutations are serializable, which is what makes the concurrency and cap checks race-safe.
4. If the store, total or date is null, `scans.fail` runs and the route returns 422 `missing_fields` with a `missing` array; the UI names each missing field (the store message says it is either not in the list or unreadable). Otherwise `scans.complete` re-checks the storage caps, inserts into `receipts`, increments the `stats` singleton, and marks the event `done`. Failed scans still count toward the rate limit.

`/api/quota` returns the same numbers via `scans.getQuota` so the UI can show remaining scans.

## Convex conventions

- All tunable limits live in `convex/limits.ts`: per-user and per-IP scans per hourly window, 1 concurrent scan per user, per-user and global receipt caps, and the rows per page in the receipts and stores modals. Client code imports `LIST_PAGE_SIZE` from there too.
- Write and identity-taking functions are public Convex functions guarded by a `secret` arg checked by `assertServer()` in `convex/lib.ts`. Only the Next.js server, which holds the secret, can call them. `receipts.list` and `receipts.summary` are public with no secret and must never return `userKey`.
- The global receipt count is kept in the `stats` table (`name: "global"`) instead of counting rows; keep it in sync if you add deletion.
- `crons.ts` runs `scans.pruneOldEvents` hourly to delete `scanEvents` older than the window.
- Import Convex code from the frontend through the `@convex/*` path alias (tsconfig maps it to `./convex/*`).

## OCR (`src/lib/ocr/`, runs in the browser)

- `scan.ts`: `loadOcrEngine()` lazily creates one shared Tesseract.js worker (`OEM.LSTM_ONLY`, `PSM.SINGLE_COLUMN`, i.e. `--oem 1 --psm 4`, languages eng+spa) with `workerPath`/`corePath`/`langPath` pointing at `/tesseract/*`. Never let it fall back to its jsDelivr defaults. `scanReceipt()` decodes the photo with EXIF rotation, converts it to grayscale scaled to a ~3200px long side, and runs passes until `isConfident`. Later passes are skipped once the 30 s budget is nearly spent. The first pass always completes.
- `preprocess.ts`: pure pixel ops on `GrayImage`, mirroring Pillow. `preprocessVariants()` yields shadow-removed + Otsu-binarized, shadow-removed grayscale (sharpened), then plain grayscale (autocontrast + sharpen).
- `parser.ts`: pure, line-based heuristics, covered by `parser.test.ts` (which includes real Tesseract output from Chilean boletas). It's a port of the former Python parser. `analyze(text)` turns one pass into scored `Evidence` (Maps, so ties go to the first candidate seen), `combine()` sums the evidence across passes, and `isConfident()` decides when to stop running passes. `similarity()` reimplements `difflib.SequenceMatcher.ratio()` for fuzzy store matching.
  - Totals: the amount on a line containing "total". "Strong" qualifiers (total boleta, total a pagar, grand total…) score 3 and a plain "total" scores 2. Sub-Total, Total Neto/Afecto/Exento/IVA/Dcto, item-count and `%` lines are excluded. A matching card-payment line (T.Debito, Transbank, Tar Deb…) adds +1, and so does an IVA line consistent with 19%. If no total line is found it falls back to the largest money-like amount not on a payment line.
  - Amounts: handles `1,234.56`, `1.234,56` and peso-style `$12.990`.
  - Dates: a date on a Fecha/Emisión/Date line beats other dates. Resolución/vencimiento lines are skipped. Ambiguous numeric dates use `parserConfig.dateOrder` (from `NEXT_PUBLIC_DATE_ORDER`, inlined at build): `AUTO` (default) is DMY when the text looks Spanish, otherwise MDY.
  - Store name: only names in the Convex `stores` table (`convex/stores.ts`, starts empty; the admin adds stores with `npx convex run stores:upsert '{"name":"...","aliases":["..."]}'` or the dashboard), passed into `scanReceipt(file, stores)` / `analyze(text, stores)` and matched fuzzily. The highest-printed match wins.
  - Language/currency: `detectLanguage` counts Spanish vs English receipt words (`SPANISH_WORDS`/`ENGLISH_WORDS`), and passes vote. `es` → `CLP`, `en` → `USD`. A printed `US$`/`USD`/`CLP` overrides it. Currency is only ever `USD`, `CLP` or `null` (the scan route enforces this too). The language also drives the `AUTO` date order.
  - Every field is `null` rather than a guess.

## Environment

`.env.local` (template in `.env.example`): `CONVEX_DEPLOYMENT`, `NEXT_PUBLIC_CONVEX_URL`, `CONVEX_SERVER_SECRET`, and optionally `NEXT_PUBLIC_DATE_ORDER`. Server env is read lazily via `src/lib/server/env.ts`, so `next build` works without secrets. On Vercel, keep Root Directory at the repo root and set the build command to `npx convex deploy --cmd 'npm run build'`.
